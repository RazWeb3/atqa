# ATQAデモ用サンプル 音声作成ガイド

`public/demo/atqa-demo-sample.json` の音声を作成するためのガイドです。
人が読み間違える必要はなく、**実際のTTSエンジンに読ませるだけ**で検知ユニットの誤読が再現されます。

## 作成ルール

- 1ユニット = 1ファイル。ファイル名は `demo-doc-1.mp3` 〜 `demo-doc-5.mp3`
- **正常ユニット（1・3・5）**: JSONの `tts.text`（補正済み原稿）をTTSに読ませる → 正しい音声
- **検知ユニット（2・4）**: 下記の**録音用原稿（誤読をかなで埋め込み済み）**をTTSに読ませる
  → 誤読が**確実に**音声に入る。表示テキストをそのまま読ませる方式は、TTSが
  たまたま正しく読むと誤読のない音声になり、デモの前提が崩れるので非推奨
- クラウド音声推奨（読みが安定しているため、正常ユニットが確実に正常判定になる）
- 音声作成後、JSONの各 `tts.audioPath` と `assetBaseUrl` を実際の配置先に合わせる
  （配信ホストは `ALLOWED_AUDIO_HOSTS` に含める必要あり・HTTPS必須）

## demo-doc-2.mp3（検知：漢字の誤読）

**下記の録音用原稿をそのまま合成**します（誤読をかなで埋め込み済み）:

> 日本語の音声合成は、漢字の読み分けが苦手です。例えば、作業が**ひとだんらく**したら報告する、この機能が品質保証を**たんいます**、といった普通の文でも誤読が起こります。このユニットの音声は、原稿をそのまま音声合成に読ませたものです。どこが誤読されたか、エーアイ検査で確かめてみてください。

| 語 | 期待読み | 埋め込む誤読 |
| --- | --- | --- |
| 一段落 | いちだんらく | **ひとだんらく**（実測された誤読） |
| 担います | にないます | **たんいます** |

※ 表示テキスト（`text`）をそのまま読ませる方式だと、TTSがたまたま正しく読んで
誤読のない音声になることがあるため、かな埋め込みで誤読を確実に再現します。
（「補正を忘れた原稿をTTSが誤読した音声」と同じものができます）

## 仕組みの補足

- 検査の期待読みは表示テキスト（`text`）から導出され、実音声と照合されます。
- `tts.text` は「TTSが本来読むべき正しい原稿」。これを合成すれば正しい音声＝正常判定になります。
- 検知ユニットは表示テキストを未補正のまま合成することで、
  「補正を忘れた原稿をTTSが誤読した」という実運用そのままの状況を再現します。
- 語の誤読はTTSエンジン（Android / iPhone / クラウド音声）ごとに異なります。
  採用中の語（一段落・担います・.gitignore）は実測で誤読が確認されたものです。
  エンジンを変える場合は、合成した音声を聴いて誤読の有無を確認してから採用してください。
- 音声認識（STT）は誤読を正しい表記に自動補正して転写することがあるため、
  検知はGeminiが音声そのものを聴いた判定に依存します。誤読が音声に実在しても
  検知されない場合は、その語の誤読がはっきり発音されているか確認してください。
